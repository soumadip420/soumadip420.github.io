Pixi

Code
Why I built it

I wanted to understand how a real social platform fits together end to end — authentication, media uploads, and live interactions — rather than building another single-purpose app.

What it does

Pixi is a Django social media app where users create profiles, post images with descriptions, and interact through likes, comments, and saves. The feed shows each author's name, profile picture, and relative post time, and lets people like, save, or open comments without leaving the page. An admin dashboard handles post oversight.

What I learned

How to tie authentication, media uploads, and social interactions like likes and comments into one cohesive Django app, and how to keep a feed feeling responsive without a page reload for every action.

Key features
  • Auth & profile management
  • Posts with images & descriptions
  • Likes, comments & saved posts
  • Interactive feed
  • Admin post dashboard

Joke Generator

Code
Why I built it

I wanted hands-on practice consuming a public REST API from Python and turning a raw JSON response into something pleasant to actually use in a terminal.

Password Manager

Code
Why I built it

I wanted to go beyond basic CRUD scripts and build something that combined data security concerns — password generation and strength checking — with a proper multi-file architecture.

What it does

A command-line password manager that stores account credentials in SQLite, organized by category. It can search, update, delete, and restore accounts (deleted ones move to an archive instead of disappearing), generate strong random passwords, and score password strength.

What I learned

Structuring a Python app across multiple modules, SQLite CRUD operations, generating secure passwords with the secrets module, and writing cleaner code by splitting logic into reusable helper files.

Key features
  • Add, search, update & delete accounts
  • Restore deleted accounts
  • Strong password generator
  • Password strength checker
  • Category organization

Customer & Order Management System

Code
Why I built it

I'd worked through plenty of isolated Django tutorials, so I built this to see how authentication, models, forms, signals, and a real database actually work together in one application.

What it does

A customer and order management system with separate admin and customer dashboards. Admins manage products, customers, and orders and see delivery/pending stats; customers view their own order history and status, and update their account details. New users are automatically set up with the right role and profile through a Django signal.

What I learned

How to connect templates, views, forms, models, authentication, permissions, signals, and filtering into one complete PostgreSQL-backed application — moving past writing each piece in isolation.

Key features
  • Role-based admin & customer dashboards
  • Product, order & customer management
  • Auto profile creation via signals
  • Order filtering by product/status/date
  • Email password reset

Student Management System

Code
Why I built it

I wanted to practice a full CRUD system that doesn't just delete data outright, but archives it — closer to how real record-keeping systems behave.

What it does

A terminal-based student database manager: add, view, count, and update student records, with deleted records moved into a separate archive table (complete with a removal timestamp) instead of being erased.

What I learned

Using try/except/finally to make sure database connections always close safely, and using parameterized queries throughout to avoid SQL injection.

Key features
  • Add, view & update student records
  • Record count
  • Archive instead of hard delete
  • Deleted-records history view
